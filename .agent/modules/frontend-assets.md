# Module: Frontend Assets

**Created:** 2026-09-16
**Last Updated:** 2026-09-16
**Status:** Active

## Description

The asset pipeline: SASS and vanilla JS in `src/` are bundled by `build.mjs`
(esbuild + `esbuild-sass-plugin` + PostCSS) into `static/`, which nginx serves.
There is no framework, no module federation and no HMR — only rebuild-and-refresh.

## Architecture

```
src/js/*.js            -> static/js/<name>.min.js    (each file is its own bundle)
src/js/admin/*.js      -> static/admin/js/<name>.min.js
src/sass/*.sass|scss   -> static/css/<name>.min.css
src/sass/admin/*.scss  -> static/admin/css/<name>.min.css
src/js/utils, components -> bundled into the entry points that import them
```

`build.mjs` discovers entry points with glob:

- Main JS: `src/js/*.js`, excluding `admin/`, `components/`, `utils/`.
- Main SASS: `src/sass/*.{sass,scss}` at the top level; **`_`-prefixed files are
  skipped** (so partials must keep the underscore).
- Admin: everything in `src/js/admin/` and `src/sass/admin/` (again skipping `_*`),
  compiled to a **separate output tree** so admin CSS never leaks into the public
  bundle.
- `entryNames: '[name].min'` — output is always `<name>.min.js` / `<name>.min.css`.
- CSS emitted by the JS pipeline (a `.js` entry importing SASS) is moved into
  `static/css/` afterwards by `moveGeneratedCssFromJs`.

Each bundle is `format: 'iife'`, `target: es2020`, minified unless `--dev`.

## Usage

```bash
npm run watch:dev   # during development
npm run build       # what CI runs; minified, no sourcemaps
```

Run `npm run watch:dev` in a terminal rather than configuring IDE file watchers —
`BUILD.md` documents PyCharm watchers, but they point at the same `build.mjs`
invocation and are optional.

## Cache Busting — `{% md5url %}`

Templates reference assets through a custom tag, not `{% static %}`:

```django
<link href="{% md5url 'css/base.min.css' %}" rel="stylesheet">
<script src="{% md5url 'js/base.min.js' %}"></script>
```

`exhibition/templatetags/custom_tags.py::UrlCache` reads the file from
`settings.STATICFILES_DIRS[0]` when set (debug), otherwise `settings.STATIC_ROOT`,
computes an MD5 of the **contents** and appends `?v=<first-8-chars>`. The result is
memoized in a **class-level dict, i.e. per worker process**.

Consequences:

- The fingerprint source of truth is the file on disk, not a manifest — this is the
  *only* cache-busting mechanism in the project; there is no hashed storage
  (`STATICFILES_STORAGE` was removed, see `AGENTS.md` gotcha #7).
- A worker that has already served an asset keeps returning the old `?v=` value until
  the process restarts. Deployment restarts gunicorn, so a release is fine; a manual
  `collectstatic` on a running server is not.
- If the file is missing, `calc_md5` raises `FileNotFoundError`, which is **not**
  caught (only `IsADirectoryError` is) — a template can hard-fail the page when an
  asset is absent.

- CSS can also come from JS: `src/js/components/slider.js` imports `swiper/css`, so the
  bundler emits a stylesheet alongside the `swiper.js` entry and
  `moveGeneratedCssFromJs` relocates it to `static/css/swiper.min.css`. That is the
  only entry producing CSS this way.

## Dependencies

### External

Bundled into client code: `jquery`, `swiper`, `isotope-layout` +
`imagesloaded` (masonry/filtering), `lazysizes`, `highlight.js`.
Build-time only: `esbuild`, `esbuild-sass-plugin`, `sass`, `postcss`,
`postcss-import`, `autoprefixer` (invoked with `overrideBrowserslist: last 3 versions`,
so the `browserslist` block in `package.json` is **not** what autoprefixer uses).

### Legacy files in `static/`

`static/` contains leftovers from the pre-esbuild (Gulp) pipeline —
`css/designer-page.min.css`, `css/jquery-ui.css`, `css/jquery.fileupload-ui.css`,
`css/multiupload.css`, `js/jquery.min.js`, `js/lazysizes.min.js`. They are
untracked, not generated by `build.mjs`, and not referenced by any template or script.
Do not copy them as a pattern, and do not assume everything in `static/` has a source.

## Gotchas

- **Stale artifacts in `static/` are not garbage-collected.** The build only writes
  entries it discovers; removed entry points leave their output behind, so `static/`
  accumulates files with no source (see above).
- **`static/js` and `static/css` are gitignored, so a fresh clone has no bundles until
  `npm run build` runs.** On top of this, `collectstatic` on the server gathers the
  static trees shipped by the installed packages (CKEditor, jazzmin admin assets,
  etc.), which is why directories such as `static/ckeditor/` exist only after a
  collectstatic run and are not part of this repo.
- **`static/css/base.min.css` and `static/js/base.min.js` are tracked exceptions**
  (see `AGENTS.md` gotcha #2), so any local `npm run build` shows them as modified.
  They are the only build outputs where a version-control conflict is possible.
- **Fonts and images are `external`** in every esbuild config (`../fonts/*`,
  `../images/*`) — they are resolved at runtime by URL, not inlined. Paths inside
  SASS must therefore match the deployed `static/` layout.
- **Sourcemaps are emitted only with `--dev`**, landing next to the CSS/JS in the same
  directory, so a production `static/` has none.
- Adding a new page-level JS file requires no `build.mjs` change — but the template must
  reference the resulting `<name>.min.js` explicitly; nothing auto-injects bundles.
